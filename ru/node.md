<header class="page-header"><p class="eyebrow">Нода</p><h1>Нода VALDR</h1><p class="lead">VALDR Node проверяет данные blockchain, хранит локальное состояние цепочки и обменивается блоками и транзакциями с peers.</p></header>
<p>Нода является локальным источником protocol validation. Wallet, Miner и Explorer могут использовать интерфейсы ноды, но не заменяют её проверку.</p>
<h2>1. Запуск ноды</h2>
<p>Нода запускается с выбранным сетевым профилем VALDR и постоянным каталогом данных. Перед обычной работой она проверяет identity сети, состояние хранилища и текущий chain tip. Persistent storage позволяет перезапустить ноду без потери уже проверенного состояния blockchain.</p>
<h2>2. Подключение к peers</h2>
<p>Нода подключается к P2P-сети и устанавливает соединения с совместимыми VALDR peers. Перед обычным обменом сообщениями protocol проверяет сеть и версию. Ограничения числа peers, размера сообщений, rate limits и штрафы за malformed traffic защищают ноду от злоупотреблений.</p>
<h2>3. Синхронизация blockchain</h2>
<p>Если нода отстаёт, она запрашивает недостающие данные цепочки у peers и синхронизируется к лучшей валидной цепочке. Конкурирующие валидные ветки сравниваются по cumulative chainwork, а не только по высоте. Если обнаружена лучшая валидная ветка, нода может выполнить reorganization с корректным восстановлением затронутого UTXO state.</p>
<h2>4. Проверка транзакций</h2>
<p>Входящие транзакции нода проверяет самостоятельно. Проверяются структура транзакции, подписи, используемые UTXO, право владения, доступная сумма, правила комиссии и конфликты. Корректные неподтверждённые транзакции могут попасть в mempool и распространяться peers согласно локальной relay policy.</p>
<h2>5. Проверка блоков</h2>
<p>Каждый полученный или локально найденный блок проходит consensus validation до включения в active chain. Нода проверяет связь с предыдущим блоком, структуру блока, timestamp rules, difficulty, Proof of Work, транзакции, изменения UTXO и ограничения reward. Некорректные блоки отклоняются.</p>
<h2>6. Работа с локальными приложениями</h2>
<p>Нода предоставляет RPC-интерфейсы для status, chain information, synchronization, balances, transactions, mining information и других операций. По умолчанию RPC привязан к localhost. Privileged operations требуют дополнительной защиты, если удалённый доступ включён намеренно.</p>
<p>Wallet может отправлять ноде подписанные транзакции. Miner может получать block templates. Explorer может использовать read-only RPC для индексации публичных данных blockchain.</p>
<h2>7. Контроль состояния ноды</h2>
<p>Работающая нода может предоставлять chain height, tip hash, chainwork, peer count, mempool state, synchronization status и RPC health. По ним оператор проверяет, что нода работает и следует ожидаемому состоянию сети.</p>
<h2>Роль ноды</h2>
<p><strong>Запуск → проверка локального состояния → подключение peers → синхронизация → проверка транзакций → проверка блоков → обновление chain state → распространение валидных данных.</strong></p>
<p>Именно Node локально обеспечивает соблюдение consensus VALDR. Остальные компоненты могут отображать данные, подписывать транзакции, майнить или выполнять запросы, но принятие blockchain state определяется проверкой ноды.</p>
