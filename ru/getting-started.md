<h1>Начало работы с VALDR</h1>
<p class="lead">Проходите систему по порядку: проверьте программу, создайте кошелёк, запустите ноду, синхронизируйтесь, получите или намайньте VDR, отправьте транзакцию и проверьте результат.</p>
</header>

<div class="note"><strong>Текущий этап:</strong> разработка VALDR сосредоточена на готовности Devnet/Testnet. Testnet software, параметры сети и Testnet VDR не следует считать финальными параметрами Mainnet.</div>

<h2>1. Получите проверенную сборку VALDR</h2>
<p>Используйте только официальный build, для которого опубликованы точная версия, source revision, целевая платформа, размер файла, SHA-256 и release provenance.</p>
<p>Если проверенного публичного артефакта для вашей платформы ещё нет, не заменяйте его случайным исполняемым файлом только потому, что его имя похоже на официальное.</p>

<h2>2. Проверьте артефакт</h2>
<p>Вычислите SHA-256 локально и сравните его с checksum, опубликованной именно для этого файла. Если опубликованы provenance или signing data, проверьте и их до запуска.</p>
<p>Если версия, checksum или provenance не совпадают, остановитесь и выясните причину.</p>

<h2>3. Создайте или откройте Wallet</h2>
<p>Создайте кошелёк локально и защитите его credentials. Wallet создаёт и хранит адрес VALDR и локально подписывает транзакции.</p>
<p>Private keys не должны передаваться через P2P или RPC. Для получения VDR передавайте только публичный адрес.</p>

<h2>4. Запустите VALDR Node</h2>
<p>Запустите ноду с нужным network profile и постоянным data directory. Node проверяет blockchain, хранит локальное состояние цепочки и подключается к совместимым peers.</p>
<p>Privileged RPC по умолчанию должен оставаться локальным, если удалённый доступ не включён специально и не защищён.</p>

<h2>5. Дождитесь синхронизации</h2>
<p>Перед использованием балансов, Mining или статуса транзакций дождитесь синхронизации ноды с сетью.</p>
<p>Проверьте synchronization status, текущую height, chain tip и peer connectivity. Пока Node догоняет сеть, у неё ещё нет последнего проверенного chain state.</p>

<h2>6. Получите VDR в активной сети</h2>
<p>VDR может поступить в кошелёк через валидную входящую транзакцию или через Mining в активной development network.</p>
<p>В Testnet VDR используется для проверки протокола и не определяет финальную экономику Mainnet и не является обещанием денежной стоимости.</p>

<h2>7. Отправьте транзакцию</h2>
<p>Создайте транзакцию в Wallet, укажите адрес получателя и сумму и подпишите её локально. Подписанная транзакция передаётся Node.</p>
<p>Node проверяет её и, если она соответствует применимой policy, может добавить в mempool и распространить peers.</p>

<h2>8. Дождитесь включения в блок</h2>
<p>Транзакция в mempool ещё не подтверждена. Miner должен включить её в candidate block и найти корректный Proof of Work. После этого найденный блок должен пройти независимую node validation.</p>

<h2>9. Проверьте результат</h2>
<p>После принятия блока проверьте транзакцию через свою Node или через VALDR Explorer после публикации официального Explorer endpoint.</p>
<p>Explorer показывает данные блоков, транзакций и адресов, но источником protocol truth остаётся Node.</p>

<h2>Рекомендуемый путь</h2>
<p><strong>Проверка software → Wallet → Node → Synchronization → Получение или Mining → Send → Block confirmation → Explorer verification.</strong></p>
